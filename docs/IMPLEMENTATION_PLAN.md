# 한끼이음 구현 계획

## 1단계 — 데모 프론트엔드 (완료)

- npm workspace와 `apps/web` Next.js App Router 프로젝트 구성
- 공통 디자인 시스템, 내비게이션, DEMO 배지, 반응형/접근성 기반 구현
- 메인, 캠페인, 내 식사권, 복지기관, 식당, 투명성 화면 구현
- 브라우저 저장 상태 기반 후원 → QR 발급 → 식사 제공/가상 정산 → 완료 흐름
- 1~2초 가상 거래 상태, QR 생성/다운로드, 직접 입력, 샘플 선택, 중복 사용 거부
- 상태 로직 자동 테스트와 타입·린트·빌드, 데스크톱/모바일 브라우저 검증

## 2단계 — 스마트 컨트랙트와 로컬 온체인 (완료)

- `packages/contracts` Hardhat 프로젝트 및 Solidity 컨트랙트 구현
- Campaign/Donation/Voucher, 역할, 일시정지, 재진입 방지, 이벤트 구현
- 명세의 정상/실패/보안 단위 테스트 전체 작성
- 로컬 Hardhat 배포 스크립트와 개발 문서 작성
- Hardhat Ignition 로컬 배포 모듈과 개발 문서 작성
- Wagmi/Viem/MetaMask 및 Sepolia 연결은 의도적으로 제외

## 3단계 — 프론트·컨트랙트 통합

- 데모/온체인 어댑터 분리와 환경변수 기반 전환
- MetaMask 연결, 네트워크 전환, 트랜잭션 상태/오류 처리
- 암호학적 QR 비밀값 생성, 해시 발급, 지정 식당 사용 및 정산 연결
- 온체인 이벤트와 후원자 타임라인·투명성 통계 동기화

## 4단계 — Sepolia와 출시 준비

- Sepolia 배포/검증, 테스트 지갑 준비 및 안전 경고 문서화
- 전체 E2E, 접근성, 오류/빈 상태, 브라우저 호환성 점검
- README 실행·배포·2~3분 발표 시나리오 완성
- 비밀정보와 실제 자금이 포함되지 않았는지 최종 보안 검토

## 데이터 흐름

`후원자 데모 후원` → `식사권 생성(전달 대기)` → `기관의 익명 대상자/식당 지정` → `일회용 QR 발급` → `식당 유효성 확인` → `식사 제공 완료` → `가상 정산 기록` → `통계와 후원자 타임라인 갱신`

## 현재 제외 범위

Wagmi, Viem, 실제 MetaMask, 프론트·컨트랙트 통합, Sepolia RPC·배포·거래는 아직 구현하지 않는다. UI의 지갑·거래·탐색기 표시는 계속 명확한 데모 데이터로만 제공한다.
